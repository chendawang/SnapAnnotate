# 测试策略

## 测试层次

1. **Core 单元测试**：命名、状态转换、选区几何、历史规则；
2. **平台契约测试**：快捷键、屏幕枚举、剪贴板和保存语义；
3. **渲染测试**：标注命令与最终像素快照；
4. **手工矩阵**：多屏、缩放、HDR、远程桌面、窗口遮挡；
5. **性能测试**：触发到冻结、内存峰值、连续截图稳定性。

## 必测失败路径

- 用户按 Escape 取消；
- 快捷键被占用；
- 保存目录不可写；
- 剪贴板暂时被其他进程占用；
- 显示器在截图过程中拔插；
- 历史记录指向的文件被外部删除；
- 第二实例无法连接第一实例命名管道；
- 托盘资源释放后进程无法退出；
- 启动目录不可写或快捷方式被 Windows 禁用；
- AI 目标未安装、未登录或请求超时。

## M0 命令

```powershell
dotnet test ScreenshotAssistant.slnx
```

当前单元测试覆盖文件名合法化、UTC 时间格式、像素区域规范化和 BGRA 像素裁剪。后续每个领域规则都应先进入 Core 测试，再连接 UI。

Windows 截图链路按照 [M1 手工验收](M1_MANUAL_TEST.md) 验证；在建立稳定的桌面测试宿主前，不把依赖真实显示器和剪贴板的测试混入 Core 单元测试。

`--capture-diagnostics <报告路径>` 用于本机只读验收：记录显示器物理边界和有效 DPI，在内存中连续捕获虚拟桌面 10 次并输出 JSON。它可以验证多屏画布、混合 DPI 环境覆盖和连续底层捕获，但不能替代跨屏拖动选区、标注工具及最终像素边界的人工目视检查。
