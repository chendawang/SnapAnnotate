# 编码规范

## C#

- 使用文件范围命名空间、可空引用类型和隐式 using；
- 类型、公开成员使用 `PascalCase`，局部变量和参数使用 `camelCase`；
- 接口以 `I` 开头，异步方法以 `Async` 结尾；
- 时间使用 `DateTimeOffset`，持久化时统一 UTC；
- 文件路径使用 `Path` API，不手写分隔符；
- 正常的用户取消使用结果类型，不抛异常；
- 捕获外部异常时保留原异常作为 inner exception；
- 公共 API 参数尽早校验；
- 默认使用 `CancellationToken` 贯穿截图、存储和 AI 调用；
- 禁止 `.Result`、`.Wait()` 和 `async void`，UI 事件处理器除外。

## Avalonia

- AXAML 只负责布局和视觉状态；
- 业务动作通过 ViewModel/用例服务执行；
- Code-behind 仅处理纯视图行为和工程组合阶段的临时导航；
- 颜色、圆角、间距和字号集中为资源，禁止在多个页面复制魔法值；
- 覆盖层渲染与主窗口导航分离；
- 所有显示器坐标必须明确标记为逻辑坐标或物理像素。

## 文件组织

- 每个主要类型一个文件；
- 文件名与主要类型同名；
- 按业务能力组织，避免长期保留 `Helpers`、`Utils` 杂项目录；
- 不新增与 ShareX 重复的截图、热键、剪贴板、文件保存或历史实现；平台差异统一封装在 `ScreenshotAssistant.Capture` 的 ShareX 适配器中；
- SQL 迁移必须带顺序编号且只追加，不修改已经发布的迁移。

## 错误和日志

- 日志不得包含图片内容、API 密钥和完整用户输入；
- 结构化字段使用稳定名称；
- 可恢复错误给用户明确动作，不只显示“发生错误”；
- 捕获失败、保存失败、剪贴板失败和 AI 发送失败分别建模。

## 提交粒度

- 一个提交解决一个可描述的问题；
- 格式化与功能改动分开；
- 第三方代码导入单独提交并附来源、commit 和许可证；
- 不提交 `bin`、`obj`、截图样本中的隐私数据或本机配置。
