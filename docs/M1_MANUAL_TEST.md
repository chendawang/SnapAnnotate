# M1 手工验收

## 当前支持范围

- Windows 10/11；
- ShareX 虚拟桌面冻结画面；
- 多显示器、窗口/控件自动识别和鼠标矩形选区；
- 屏上标注、撤销/重做；
- `Ctrl+Shift+A` 默认保存 PNG、写入截图记录并自动复制到剪切板，Esc 取消；
- ShareX PNG 保存、Windows 图片剪贴板和 SQLite 图片历史。

## 验收步骤

1. 运行 `dotnet run --project src/ScreenshotAssistant.App/ScreenshotAssistant.App.csproj`；
2. 在任意前台应用按 `Ctrl+Shift+A`，确认主窗口从冻结画面中消失；
3. 在不同显示器悬停，确认窗口边界自动高亮；跨屏拖动选区，确认坐标正确；
4. 添加矩形、箭头、文字、马赛克和序号，执行一次撤销/重做后完成；
5. 在画图或聊天输入框中粘贴，确认剪贴板是所选图片；
6. 点击“截图到文件”完成一次截图；打开 `%LocalAppData%/ScreenshotAssistant/captures/YYYY/MM`，确认 PNG 尺寸与选区一致；
7. 确认首页“截图记录”和左侧“截图历史”都以正方形缩略图显示；点击复制图标确认图片进入剪切板，点击文件夹图标确认打开图片所在目录；
8. 点击“设置”，确认设置在主窗口右侧显示；修改快捷键、窗口识别、标注粗细、保存目录和命名模板，保存后确认下一次截图立即生效；
9. 关闭并重新启动应用，确认设置仍然存在；
10. 再次截图后按 Esc，确认没有新增 PNG 或历史记录；
11. 快速连续按快捷键，确认只打开一个截图会话；完成后再次按快捷键可立即截图；
12. 连续执行 10 次，确认没有残留冻结窗口或无法再次截图。
13. 关闭主窗口，确认进程仍在且托盘图标可双击恢复主窗口；
14. 从托盘分别触发保存文件、复制剪切板和整屏截图，确认主窗口不会意外弹出；
15. 再次启动程序，确认没有出现第二个进程窗口，已有窗口被恢复并激活；
16. 在设置中启用“登录 Windows 后自动启动”，确认启动目录生成 `Screenshot Assistant.lnk`；关闭该选项后确认快捷方式被移除；
17. 使用 `--background` 参数启动，确认程序只进入托盘且截图快捷键有效。
18. 在“快捷截图”“截图历史”“设置”之间连续切换，确认始终只有一个主窗口，右侧内容随导航更新；确认主窗口外框约为 769×630，与 PixPin 配置窗口一致。

- 全局快捷键进入冻结选区并按 Esc 取消：连续 10/10 成功，主窗口均恢复且进程响应正常；
- 多屏覆盖：通过；
- 混合 DPI 捕获覆盖：通过；
- 跨屏拖动选区的最终像素边界仍保留人工目视验收，不由内存诊断替代。

机器可读报告生成在被 Git 忽略的 `artifacts/capture-diagnostics.json`。

## 暂不通过的场景

- HDR/高级色彩的色彩保真；
- 自动化驱动 ShareX 覆盖层的 UI 集成测试；
- 混合 DPI、多屏异形排列的完整设备矩阵。

这些限制不作为已验证能力陈述，需在目标设备继续验收。

## 回滚

回滚到替换前版本需要从版本控制恢复已删除的自研 GDI、选区和剪贴板文件，并移除 `ShareX.HistoryLib` 引用。当前版本不再同时维护两套截图实现，避免后续行为分叉。
